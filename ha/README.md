# Home Assistant integration

This HA instance has **MQTT auto-discovery on the `homeassistant` prefix**. It was
previously set to `esphome/discover`, which is not a discovery prefix at all —
nothing had ever auto-discovered, which is why every other device here is declared
by hand in `configuration.yaml`.

Deliberately **not** set to `ha`: ~131 unrelated config topics live under `ha/`,
and pointing HA there would auto-create duplicates of devices already declared
manually. Only the spa and its simulator publish to `homeassistant/`.

## Dashboards

```sh
node gen-dashboard.js sim   > spa-sim-dashboard.yaml
node gen-dashboard.js real  > spa-real-dashboard.yaml
node gen-dashboard.js real hot_tub_spa   # override the entity prefix
```

Each file has two parts:

1. **`template:` block** → merge into `configuration.yaml`, then
   Developer Tools → YAML → *Reload template entities*.
2. **Lovelace view** → Settings → Dashboards → new dashboard → three-dot menu →
   *Raw configuration editor* → paste.

### Entity ids

HA folds the **device name** into the entity id (`has_entity_name`), so the real
prefix is `<device>_<entity>` — e.g. device "Hot Tub" + entity "Spa Light" gives
`switch.hot_tub_spa_light`. Verify in **Developer Tools → States** and pass the
prefix as the second argument if it differs.

### Why the temperature is handled the way it is

Everything on the wire is **Celsius**, always — a fixed `unit_of_measurement` with
a value whose unit changes at runtime is a bug, and the firmware had exactly that
until it was fixed. The dashboard therefore:

- derives **°F template sensors** with a *fixed* °F unit, and
- uses **conditional cards** keyed on `select.*_temperature_scale` to show the
  gauge in whichever scale the spa itself is set to.

A template sensor's entity id comes from its **name**, not the MQTT prefix, so the
generator computes both from one place.

**Known limitation:** the `thermostat` card renders in Home Assistant's *global*
unit system and has no per-card override without HACS. If the spa is in °F and HA
is metric, that one card disagrees with the rest. Set Settings → System → General
→ Unit system → *US customary* to make it match.

## Manual entities (fallback)

`spa-real-entities.yaml` / `spa-sim-entities.yaml` declare all 21 entities
explicitly, for use if discovery is ever unavailable. Generated by
`gen-ha-yaml.js`. Not needed while discovery works.
